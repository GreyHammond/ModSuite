01 -- The engine

Every message passes through eight filters.

First match stops the chain. All feed violations. Violations escalate to jail. Raids escalate to ban. The violation engine is the foundation -- everything plugs into it.

01

Invite filter

Blocks Discord invite links. Toggle with /automod invites.

02

Link filter

Domain whitelist/blacklist with subdomain matching and per-role/channel bypass.

03

Anti-phishing

Every URL checked against a live phishing database in real time. Fails open on timeout.

04

Word lists

Named deny lists. Whole-word for singles, substring for phrases. /wordlist group.

05

Message length

Min and max character thresholds. Empty messages (attachments only) skip min check.

06

All-caps filter

Configurable percentage threshold (default 70%). Ignores short messages.

07

Slowmode

Bot-enforced per-channel rate limit. Independent of Discord's built-in slowmode.

08

Spam detection

Message velocity, duplicate detection, mass mentions, emoji floods.

03 -- Getting started

Six steps to a running server.

Python 3.11+, a Discord bot token, and a few minutes. That's the shopping list.

  1. 01

    Create a Discord application

    Go to the Discord Developer Portal, create a new application, and add a bot. Copy the token.

    Under Bot > Privileged Gateway Intents, enable Server Members Intent and Message Content Intent.

  2. 02

    Clone & install

    git clone https://github.com/GreyHammond/ModSuite.git
cd ModSuite
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
  3. 03

    Configure environment

    cp .env.example .env
# Edit .env -- at minimum set DISCORD_TOKEN
# Optional: CORS_ORIGINS, API_HOST, API_PORT, Twitch keys, OAuth2

    That is enough to run the bot and open the dashboard on the same machine. To reach it from anywhere else, see connecting the dashboard below.

  4. 04

    Invite the bot with Administrator

    ModSuite creates roles, categories, and channels during /setup, so it needs Administrator. Generate the invite from Developer Portal > OAuth2 > URL Generator.

  5. 05

    Run the bot

    python bot.py

    The API starts automatically. Database auto-creates and auto-migrates on every startup.

  6. 06

    Run /setup in your server

    As a server admin, run /setup. Click Run Setup -- creates all default roles, channels, categories, and react-role messages. Then explore the 13 configuration panels to dial in your preferences.

04 -- Connecting the dashboard

Getting the browser talking to the bot.

The dashboard is served by the same process as the bot. Locally it just works. Everything below is about reaching it from somewhere else -- which is where CORS, the OAuth redirect, and two separate firewalls all get a vote.

  1. 01

    Local first -- confirm it works before you open anything

    With the bot running, open http://localhost:8000 on the same machine. If that fails, nothing about firewalls or CORS will fix it -- check the startup log first.

    API_HOST=0.0.0.0
API_PORT=8000
DISCORD_REDIRECT_URI=http://localhost:8000/auth/callback

    Localhost origins are always allowed, so CORS_ORIGINS can stay empty here.

  2. 02

    Open the port -- in two places, not one

    On a cloud host there are two firewalls between you and port 8000, and both have to allow it. Opening only the provider one is the single most common reason the page never loads.

    Host firewall

    # Ubuntu / Debian
sudo ufw allow 8000/tcp

# RHEL / Fedora / Alma
sudo firewall-cmd --add-port=8000/tcp --permanent && sudo firewall-cmd --reload

# Raw iptables (Oracle Cloud images need this even with ufw installed)
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 8000 -j ACCEPT
sudo netfilter-persistent save

    Provider firewall -- ingress on TCP 8000 from 0.0.0.0/0:

    • Oracle Cloud -- Networking › VCN › Security Lists › Default › Add Ingress Rule
    • AWS -- EC2 › Security Groups › Inbound rules
    • Google Cloud -- VPC network › Firewall › Create firewall rule
    • Azure -- Network security group › Inbound security rules
    • DigitalOcean / Vultr / Linode / Hetzner -- Cloud Firewall in the control panel, if you created one

    Self-hosting at home? Skip all of this and tunnel instead -- nothing gets published to the internet:

    ssh -L 8000:localhost:8000 user@your-host
  3. 03

    CORS and the redirect URI

    These two are the ones that bite. The browser refuses a cross-origin API call unless the origin is listed, and Discord refuses the login unless the redirect matches what is registered character for character.

    DISCORD_REDIRECT_URI=http://YOUR_IP_OR_DOMAIN:8000/auth/callback
CORS_ORIGINS=http://YOUR_IP_OR_DOMAIN:8000
MODSUITE_GUILD_ID=your_server_id

    Then add that exact redirect URI in the Developer Portal under OAuth2 › Redirects. A trailing slash, a missing port, or http where you registered https all count as different URIs.

    CORS_ORIGINS is an origin -- scheme, host, and port, with no path and no trailing slash. http://1.2.3.4:8000 is right; http://1.2.3.4:8000/ and 1.2.3.4 are not. Multiple origins are comma-separated.

  4. 04

    Lock down who can log in

    DASHBOARD_ALLOWED_ROLES=<Editor role ID>,<Moderator role ID>

    Leave it blank and any member of the guild can reach the dashboard. Set it before you go live, not after.

  5. 05

    Put HTTPS in front of it

    Bare http://IP:8000 sends the session cookie in the clear. If the dashboard is reachable from the internet, terminate TLS in a reverse proxy. With a domain pointed at the host, Caddy handles the certificate itself:

    # /etc/caddy/Caddyfile
modsuite.example.com {
    reverse_proxy localhost:8000
}

    Then bind the app to loopback, close 8000 to the outside, and update all three URLs -- including the one in the Developer Portal:

    API_HOST=127.0.0.1
DISCORD_REDIRECT_URI=https://modsuite.example.com/auth/callback
CORS_ORIGINS=https://modsuite.example.com

When it does not work

▸

Page never loads, request just hangs

  • A firewall is dropping the packet -- almost always the host one, since the provider rule is the one people remember
  • Confirm the process is listening: ss -tlnp | grep 8000
  • Check API_HOST is 0.0.0.0 and not 127.0.0.1
▸

Blocked by CORS policy

  • The origin in the browser bar is not in CORS_ORIGINS
  • Check for a trailing slash, a missing port, or https vs http
  • Reaching it by IP when you listed the domain counts as a different origin
  • Restart the process -- .env is read at startup
▸

Invalid OAuth2 redirect_uri

  • DISCORD_REDIRECT_URI and the portal entry differ somewhere
  • Compare them character by character, including the port and /auth/callback
  • Behind a proxy the browser sees https on 443 -- register that, not :8000
▸

Login works, then 403

  • Your account does not hold a role in DASHBOARD_ALLOWED_ROLES
  • MODSUITE_GUILD_ID points at a different server than the one you are in
  • Role IDs, not role names -- enable Developer Mode and copy the ID

v4.1.0 August 2026

Legacy booster rewards

  • Discord removes its own booster role the instant someone stops boosting, and every perk hung off it goes with it. ModSuite grants a separate, permanent role on a member's first boost instead.
  • The database row is the source of truth, not the Discord role. Roles are lost when a member leaves the server, so a record-free implementation would quietly break the promise for anyone who left and came back. on_member_join re-applies it.
  • /booster setup refuses two roles: Discord's own booster role, which is the exact thing being worked around, and any role above the bot's own, which it could never assign.
  • /booster sync backfills current boosters and restores the role to anyone whose record exists but whose role was removed by hand.
  • /booster revoke records an actor and a reason and writes to the mod log rather than deleting the row. /booster off stops future grants without touching what was already earned.

Dashboard & API

  • New Legacy Booster Rewards configuration section.
  • GET /boosters, POST /boosters/sync, DELETE /boosters/{user_id}.

Verified

  • First boost grants and records; stopping boosting changes nothing; re-boosting does not create a duplicate; leaving and rejoining restores the role; a revoked member is not restored on rejoin; a disabled guild does nothing.
